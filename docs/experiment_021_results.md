**Unsupported-answer detection recall:** 0/22 = **0%** for the semantic verifier versus 10/22 = **45.45%** for the lexical probe on these curated decisions. The semantic verifier's precision for an `unsupported` warning is **undefined** because it issued **zero** such warnings; do not report it as 100%. It made **no `uncertain` predictions**. Neither method is safe as an autonomous filter.

## Root-cause limits

The semantic verifier's model prompt requested whole-claim support plus source quotes, but the normalized output was `supported` on all 32 examples. A literal source quote confirms that some words occur in memory, **not that those words entail the candidate answer for the requested subject, attribute and time**. A supportive quote from the wrong fact or an outdated value can pass syntactic validation.

This pattern is consistent with overacceptance or question/answer anchoring by the local model, but the underlying saved raw responses were not uploaded and the exact mechanism cannot be demonstrated. Do not attribute the collapse solely to model size, prompting, or quote validation without inspecting the per-case raw responses.

## Decision for the V1.0 candidate

1. **Freeze the research experiments at Phase 14** and preserve the negative results, rather than creating a V5/V6 verifier fitted to these 32 exposed examples.
2. Keep the semantic verifier, novelty probe, and strict extractive answering **research-only**, with no power to auto-approve or block live answers.
3. Keep live `answer_generator.py` using retrieved active memories with visible evidence. It is explicitly *experimental* and **can hallucinate** (as Phase 10 P07 demonstrated).
4. Make **Smart Memory Review** the recommended saving route. The section 1 research baseline still performs broad-topic supersession, but the app now displays a prominent warning and requires explicit acknowledgement before overwriting active same-topic facts.
5. Add `scripts/v1_release_readiness.py`: verifies project files and Git ignore patterns, runs an **isolated temporary-SQLite keep/coexist/supersede test**, validates duplicate/stale-review rollback, and runs the offline unit suite. Optional `--check-models` checks only local Ollama tags. It writes uniquely numbered Git-ignored reports instead of overwriting history.
6. Complete the **manual UI and privacy release checklist** before publishing a `v1.0` tag or describing the app as portfolio-ready. No tag has been created.

## Release boundary

V1.0 is an **honestly described local-first experimental memory assistant and human-review research demonstrator**, not a fully autonomous conflict resolver or production-verified truth checker. A research-grade result requires new independent cases, multiple blind reviewers, and full pipeline evaluations; those can be scheduled after the portfolio release.

**Execution state:** Files and regression tests are committed to GitHub, but the latest unit suite, readiness CLI and interactive Streamlit smoke checks have **not** been executed on the owner's Windows environment. This report makes no claim of successful release certification.
